SCOPE IMPLEMENTED
1. Persisted settings
- DataStore-backed OwnPlay settings were added for Picture in Picture preference, resume playback preference, provider auto-refresh, provider refresh interval, and channel-logo visibility.
- Provider refresh intervals are 6 hours, 12 hours, and daily.
- Disabling provider auto-refresh removes the periodic refresh schedule.

2. Provider refresh scheduling
- WorkManager owns one unique periodic provider-refresh job.
- Periodic refresh requires network connectivity.
- The worker refreshes enabled, connected sources and applies deferred restored personalization after successful source refresh.
- Individual provider refresh failures remain best-effort and do not create a release or deployment side effect.

3. Source management UI
- Branded OwnPlay source management supports add, edit/reconnect, select, refresh, and remove for Xtream-compatible sources and remote M3U/M3U8 sources.
- Secret fields are never prefilled in the editor.
- Remote M3U/M3U8 locator input is treated as secret UI content.
- A restored source that lacks connection secrets remains disconnected until the user explicitly supplies the required connection details.
- Successful manual refresh attempts deferred personalization application for that source.

4. Backup and restore
- Ordinary backup format: strict versioned OwnPlay JSON, format version 1.
- Restore enforces format/version validation, bounded document size, bounded record counts, bounded string sizes, and strict JSON field handling.
- Storage Access Framework is used for user-selected export/import documents; no broad storage permission was added.
- Backup restores non-secret source profiles, settings, custom groups, media favorites, playback progress, and channel/group personalization when stable channel identities are available.
- Channel personalization and custom-group memberships that cannot yet resolve are retained in app-private pending restore state and retried after source refresh.
- Missing restored source profiles are created disabled and credential-free. They require explicit reconnect.
- Existing configured sources preserve their local secure credential reference.

SECURITY AND PRIVACY BOUNDARY
Ordinary backup intentionally excludes:
- Xtream usernames and passwords;
- credential-store payloads and credential secrets;
- remote M3U/M3U8 locators;
- provider playback/stream locators;
- downloaded media files and download-local references;
- refresh-state implementation data;
- custom channel-logo locators.

Android backup remains disabled in the application manifest. Source credentials remain Keystore-backed and are not moved into Room or DataStore by Stage 8.

A Stage 8 closure review found a security-sensitive restore condition: an existing configured Xtream source could have retained its local credentials while accepting a base endpoint from imported backup content. That would have allowed future refresh to send the existing credentials to an imported endpoint. The restore policy was corrected forward-only so:
- configured Xtream sources keep their existing local endpoint;
- credential-free Xtream source profiles may adopt the backup's non-secret base endpoint;
- M3U sources never import a remote locator from ordinary backup content.
Focused JVM tests cover this endpoint-preservation policy.
