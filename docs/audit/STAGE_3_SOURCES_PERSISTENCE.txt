Schema v1 review decision
-------------------------
Room schema version 1 is independently defined for the new application and separates provider metadata from local personalization/state.

Tables introduced:
- sources
- provider_categories
- live_channels
- channel_personalization
- custom_groups
- custom_group_memberships
- movies
- series
- episodes
- media_favorites
- playback_progress
- downloads
- refresh_state

Design invariants:
- source identity is stable and explicit
- provider refresh uses upsert rather than replace/delete-all semantics
- provider records carry availability + last-seen generation
- channel personalization lives outside provider-owned rows
- media favorites and playback progress live outside provider-owned rows
- source removal is the only source-level cascade boundary designed into schema v1
- no destructive migration fallback is configured
- schema starts at version 1; no old schema or migration history is present

Credential boundary
-------------------
- Room stores only a credential reference
- Xtream username/password are encrypted with an Android Keystore-backed AES-GCM key before persistence
- remote M3U locator is also kept in the secure credential store so tokenized playlist URLs are not stored as ordinary source configuration
- credential values are redacted from toString()
- network failure mapping does not include request URLs or response bodies
- no HTTP logging interceptor is installed
- Xtream persisted stream locators are opaque non-secret identifiers; provider credentials are resolved only when an actual request/stream URL is needed

Source behavior
---------------
- add/edit/select/remove source contracts
- persisted active-source ID in Preferences DataStore
- deterministic active-source fallback when the persisted source is missing or disabled
- Xtream-compatible independent endpoint client for account, Live, VOD, Series, series info, and short EPG
- deterministic tolerant M3U parser with BOM, CRLF/LF, quoted attributes, Unicode, malformed-entry isolation, and diagnostic codes
- stable Xtream identities scoped by source + provider identifier
- stable M3U identities preferring unique tvg-id, then normalized stream locator
- refresh sections are reconciled independently
- failed provider sections do not mark the last known good local section stale
- successful refresh sections advance generation and mark only unseen provider metadata unavailable
- local personalization tables are not replaced during provider refresh
