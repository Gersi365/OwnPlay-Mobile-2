Playback contracts implemented
------------------------------
- exactly one lazy PlaybackController service for the application process
- one Media3 ExoPlayer owned by that controller
- one active video target: NONE, PREVIEW, FULLSCREEN, or PIP
- serialized controller mutations and explicit surface transfer
- old SurfaceView is cleared before the next target is bound
- stale unbind requests cannot clear a newer active surface
- presentation target transfer does not reload media
- HLS support through Media3 ExoPlayer HLS
- playback snapshots intentionally exclude stream URIs and credentials
- Resume starts from saved progress
- Play from Beginning starts at zero but does not clear saved progress before
  successful playback is established
- explicit stop/retry/play-when-ready/seek/release controller operations

Dependency decision
-------------------
Media3 1.11.0 is used for ExoPlayer and HLS. It is the stable Media3 release
verified from current official Android Developers documentation during this
stage. Generic Media3 UI controls are deliberately not added because OwnPlay
requires custom transient presentation controls.

The controller explicitly pins ExoPlayer's application looper to Android's main
looper so all player calls and listener callbacks share the same application
thread. Media3 currently marks Builder.setLooper as UnstableApi. The usage site
uses androidx.annotation.OptIn with the Media3 marker, scoped only to the player
construction property. Kotlin's kotlin.OptIn is intentionally not used because
Media3's lint contract uses the AndroidX opt-in annotation.

Focused source tests
--------------------

VideoTargetOwnershipReducerTest verifies Preview/fullscreen ownership transfer,
