Scope implemented
- Replace the static Library shell data with an active-source Room-backed Library catalog.
- Preserve the approved hierarchy: Continue Watching, Movies, Series, Downloaded Media.
- Derive Continue Watching from stable playback_progress records joined to currently available movie/episode metadata.
- Keep Movie and Series ordering deterministic using provider order with stable name/id fallbacks.
- Keep Downloaded Media read-only in this phase and surface only COMPLETED rows that carry both a local reference and integrity metadata.
- Load Xtream series episode metadata on series detail open, cache episodes in the existing Room v1 episode table, and preserve cached episodes if refresh is unavailable.
- Generate episode stable IDs from source ID + Xtream episode provider ID and persist only an opaque xtream:// series identity, never the credential-bearing playback URL.
- Resolve movie and episode playback URLs only at playback time using the secure CredentialStore and XtreamUrlBuilder.
- Reuse the one process-wide PlaybackController and one FULLSCREEN VideoTarget for movie/episode playback; no second player is introduced.
- Add transient custom fullscreen controls for play/pause, seek, duration, retry, and return to Library without generic Media3 UI or technical/provider chrome.
- Persist playback progress during fullscreen playback and on exit. Play from Beginning does not erase the previous resume point before successful playback; the position-zero persistence transition occurs only after the shared player reports READY.
- Declare a tested completion rule: player ENDED or position at/above 95 percent of known duration marks the item completed.
- Add focused JVM tests for resume/beginning policy, completion threshold, deterministic Library ordering, runtime Xtream movie/episode locator construction, HLS detection, and URI redaction.
